# 05 · 威胁模型

**本文件的价值在于"未防护"那一列。** 一份只列已解决问题的威胁模型是自欺。

## 信任假设

| 假设 | 依据 | 若不成立 |
|---|---|---|
| 参与方的私钥只在其本机 | 人自己保管 `private_key_location` | 身份体系作废 |
| 存储层能限制写入路径 | **仅对象存储成立**；共享目录与 git 均不成立 | 见下表 A1、A2 |
| agent 会执行验签代码 | 取决于 adapter 实现质量 | 整层形同虚设 |
| 定时器会按时醒 | 已验证两侧都有 | 协作停滞，不产生错误结果 |

## 攻击面

### A. 身份与篡改

| # | 攻击 | 触发条件 | 现有防护 | 缺口 | 最小反制 |
|---|---|---|---|---|---|
| A1 | 伪造 `from` 发消息 | 知道合法 handle，无私钥 | **已防**：验签失败即丢弃 | — | 保持"验签不过不读 body"的顺序 |
| A2 | 篡改 `roster.json` 换掉他人公钥 | 能写仓库根 | **未防护** | 名册无任何保护，整个身份体系的根是空的 | 仓库侧保护规则；或服务端按 key 拒写非本人前缀 |
| A3 | 翻动 `done` 标志提前发布 | 能写他人前缀 | **已防**（v2）：`done` 在签名域内，翻动即验签失败 | 封帧改为 `.part` → 改名后已无位可翻。跨设备/NFS 下改名不保证原子，见 `04-transports.md` | 无需额外反制，已在 `03` 落地 |
| A4 | 重放旧消息 | 抓到一条合法消息 | `(from,nonce)` 唯一 + `.last_seen` | 读方重启后已见集合丢失 | 已见 nonce 持久化 |
| A5 | `seq` 撞号 | 两个 agent 同时读最大值 +1 | **未防护** | 并发写。共享目录无原子自增 | 各写各前缀 + 读方按 `(from,seq)` 去重，放弃全局 seq 唯一 |

### B. 注入

| # | 攻击 | 触发条件 | 现有防护 | 缺口 | 最小反制 |
|---|---|---|---|---|---|
| B1 | 合法成员在 `body` 里写"忽略以上指令" | 成员身份合法 | 部分：`type` 限定行为面，模板的「硬性边界」由代码判 | **`body` 仍可骗模型。这是纯文本方案的固有上限，不可消除** | 边界写死在模板而非 body；越权要求回 `reject` |
| B2 | 发起方垄断任务拆解 | 结构必然 | **未防护** | 它不能下指令，但能决定怎么切分——合法影响力 | `channel.md` 由人写目标，拆解结果需第二方 `offer` 确认 |
| B3 | 新人 join 提示词被塞进额外指令 | 发起方生成副本时 | 部分：模板不可改，只许填 `{{参数}}` | 参数本身是自由文本，`{{goal}}` 里能藏指令 | 参数长度上限 + 人过一遍副本 |
| B4 | 经手私钥位置 | 发起方代填 | **已防**：`{{private_key_location}}` 强制留空，只能人填 | — | 保持 |

### C. 可用性

| # | 攻击 | 现有防护 | 缺口 |
|---|---|---|---|
| C1 | 一方崩溃，频道卡住 | `heartbeat` 类型 | 无人处理心跳，停滞不可见 |
| C2 | 机器睡眠，定时器全停 | 无 | 跨天协作必然中断，无恢复语义 |
| C3 | 消息洪泛 | 无 | 一个成员可无限写文件，撑爆对方轮询 |

## 一句话结论

**当前这套防住了"发布假内容"（A1、A4、B4），没防住"篡改名册"（A2）。**
A2 是根，不修则 A1 的防护是纸糊的——攻击者不必伪造签名，直接改公钥即可。

修 A2 需要存储层能力，文本层做不到。这正是 `04-transports.md` 推荐尽快上对象存储的唯一理由。

## 本项目作为靶场

上述每一条攻击都是可实现的攻击，也是可提交的漏洞。
共享目录 + 定时器这个组合本身就是一条**绕过所有对话层防护的注入物理通道**——任何能往该目录写文件的程序，都能给两个厂商的 agent 下指令。

先建靶场，再建防护。顺序反了就没有动力。
