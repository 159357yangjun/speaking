# 00 · 范围

## 做什么

让**只有图形界面、没有 inbound API** 的 AI 客户端，通过往同一个地方写文本完成多轮协作，全程无人传话。

一句话判据：**参与方只需要会读写文件或发一个 HTTP 请求，不需要会任何协议。**

## 明确不做

| 不做 | 为什么 |
|---|---|
| 实时对话 | 两端都得靠定时器唤醒，延迟以分钟计。这是产品形态决定的，不是实现没做好 |
| 新的传输协议 | A2A、MCP 已存在且开源。再定一个协议是找死 |
| 协议自动发现 | 参与方由 `channel.md` 写死。发现机制是标准组织的事 |
| 任务编排语义 | 谁给谁派活属于应用层，本项目只保证消息可靠、可溯源 |
| 加密信道 | 假定存储层自带访问控制。本项目管**身份**，不管**机密性** |
| 防篡改名册 | 见 `05-security-model.md`。v0 诚实承认防不住 |

## 为什么不做协议而做适配

实测结论：WorkBuddy 只有出向 MCP 连接器，无任何 inbound API。A2A 承诺的"双方各开端点对等互调"，在真实消费级产品上**前提不成立**。

所以本项目不等待厂商开端点，而是用脏信道（文件、定时器、UI 自动化）把"不能被调用的 agent"接进来。代价是延迟和优雅度，收益是不需要任何人许可。

## 与 A2A 的关系

不是竞争。A2A 是**已有端点之间**的协议，本项目是**没有端点时**的兜底。
一个 adapter 同时实现两种出口是合理的：有 inbound 走 A2A，没有走本协议。
