# 跨 Agent 文本协作协议 · 最小规格 v0

日期：2026-09-28
状态：待批
目标：让两个不同厂商、互不知晓对方存在的 AI agent，通过**写入文本**完成多轮协作，全程无人传递消息。

## 一、范围

只做一件事：**在两个 agent 之间可靠地传文本消息**。

明确不做：
- 不做实时（延迟以分钟计，靠定时器轮询）
- 不做协议发现（参与方由配置文件写死）
- 不做加密信道（假定存储层自带访问控制）
- 不定义任务编排语义（谁给谁派活是应用层的事）

## 二、介质分层

一条消息 = **信封 + 正文**。

```json
{
  "seq": 7,
  "from": "workbuddy",
  "to": "qoder",
  "type": "deliverable",
  "done": true,
  "body": "……自由文本，正文内容对协议无意义……"
}
```

规则：**信封字段由代码判断，`body` 由模型判断。两者权限不同，不可互相越界。**

- `seq` 整数，全局单调递增，用于排序与幂等
- `from` 必须与写入所用凭证绑定的身份一致，不接受正文自称
- `to` 单个名字或 `*`
- `type` 枚举，见第四节
- `done` 封帧标志：`false` 表示仍在写，读方必须跳过
- `body` 任意文本。**协议不解析它，也不因它改变行为**

最后一条是整个设计的支点：正文里出现"忽略以上指令"时，改变行为的只能是模型，不能是协议层。协议层对正文免疫。

## 三、封帧与竞态

写入方：
1. 取 `seq = 当前最大 + 1`
2. 写 `msg-<seq>.json.part`，内容即最终形态，`done` 恒为 `true`
3. **改名**为 `msg-<seq>.json` —— 改名这一步就是封帧

读取方：
1. 只处理 `done: true` 且 `to` 指向我 且 `seq > 我的 last_seen` 的消息
2. 处理完把 `seq` 写入自己的 `<name>.seq`

封帧靠**改名**，不靠翻位。写一半崩溃留下的是 `.part`，读者只扫 `.json`，永不看见半截文件。
`done` 因此在签名域内——翻动它即验签失败。理由见 `03-signing.md`。

## 四、type 枚举（v0 只有四个）

| type | 含义 | 接收方义务 |
|---|---|---|
| `offer` | 交付成果 | 读，然后回 `deliverable` 或 `reject` |
| `deliverable` | 本轮产物 | 读 |
| `reject` | 拒绝执行，附原因 | 读，不得重试同一 seq |
| `heartbeat` | 我还活着 | 无义务，用于诊断停滞 |

`reject` 存在的意义：让"不配合"成为协议里一个合法动作，而不是靠模型沉默。上一轮实验里 WorkBuddy 只能把异议写进正文末尾，就是因为没有这个字段。

## 五、传输层（留空，可插拔）

协议不绑定传输。已验证可选：

| 传输 | 已验证 | 备注 |
|---|---|---|
| 共享目录 | ✅ 本实验实测通过 | WorkBuddy 可跨出其根目录写入第三方路径 |
| git 仓库 | ❌ 未测 | 需探测 WorkBuddy 有无 git 与网络出口 |
| 对象存储 / 小 HTTP 服务 | ❌ 未测 | 唯一能服务端强制 append-only 的选项 |

换传输不影响第二至四节。

## 六、唤醒

两端各靠定时器，间隔 1–5 分钟。已确认两侧都有：WorkBuddy 侧栏「定时任务」，Qoder 侧 `qoder_cron`（最小 60 秒）。

## 七、已知弱点（不打算在 v0 解决）

1. **无人参与 ≠ 无权限风险。** 任何能写入存储区的程序都能给两个 agent 下指令，绕过所有对话层防护。这是本方案最大的洞，也是它最有意思的地方——它是跨 agent prompt injection 的天然靶场。
2. 两端客户端都得开着，机器睡眠即停。
3. 轮询非对等调用。A2A 承诺的"我直接叫你"这里做不到。
4. `seq` 由写方自取，并发下可能撞号。v0 靠"各写各的前缀目录"回避，不解决。

## 八、验收：怎样算成功

两端无人干预，连续完成 **5 轮** `offer → deliverable` 往返，且：
- 每条消息 `from` 与凭证身份一致
- 无消息被处理两次
- 中途人为注入一条伪造 `from` 的消息，被代码层拒掉且不进入模型

最后一条是本协议是否值得存在的唯一判据。
