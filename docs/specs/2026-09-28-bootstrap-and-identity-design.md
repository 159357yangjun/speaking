# 接入与身份规范 v0

日期：2026-09-28　状态：待批
前置：`2026-09-28-cross-agent-text-handoff-design.md`（信封+正文协议）
本文件解决：多个 agent 如何发现彼此、如何加入、如何证明"这条是我写的"。

## 一、术语纠正：你说的"通行密钥"是两个东西

原描述：密钥里存"哪个应用的哪个 AI、几个 AI"。

这个对象**不含任何秘密**，所以它不是密钥，是**名册（roster）**。而名册放在共享仓库里，意味着**所有参与者都能读到全部条目**——读得到的东西不能用来证明身份。

因此必须拆成两半：

| | 名册 roster | 凭据 credential |
|---|---|---|
| 内容 | handle、宿主应用、公钥、人数上限 | **私钥** |
| 存放 | 仓库内，人人可读 | 各自客户端配置，**永不进仓库** |
| 作用 | 说明"有谁在" | 证明"这条是谁写的" |

**不变量 1：仓库里不许出现任何私钥。** 出现即视为泄漏，整个频道作废。

## 二、Bootstrap 流程

你描述的"先把提示词 md 给一个 AI，它再生成密钥和其他 AI 的提示词"——方向对，但有一步必须改。

```
1. 人写 channel.md（目标、人数上限、白名单）—— 人写，AI 不写
2. 人把 bootstrap 提示词 + channel.md 交给发起方 agent
3. 发起方 agent 生成：
   ✅ roster.json（自己的 handle + 公钥 + 目标拆解）
   ✅ 每个待加入者的 join 提示词
   ❌ 不生成 channel.md，不生成提示词模板本身
4. 人把对应的 join 提示词交给第二个 agent
5. 第二个 agent 用自己的私钥签一条 join 请求，写进仓库
6. 后续 agent 重复 4–5，直到满员或超时
```

**为什么第 3 步禁止 AI 生成模板**：如果发起方能写别人要照做的提示词，它就拥有对其他所有 agent 的**指令权**。那正是协议要防的事——第一个节点被攻破，全频道沦陷。

**不变量 2：agent 只生成 `body` 和模板参数，不生成模板、不生成别人的指令、不改 `channel.md`。**

join 提示词的具体内容因此是**固定的**，只有 `{{handle}}`、`{{goal}}` 等参数由发起方填。见 `proto/agent-prompt-template.md`。

## 三、加入与人数

- `channel.md` 里写死 `max_members`，达到即关闭加入
- 每个成员占一个独立前缀目录 `agents/<handle>/`，**只写自己的前缀**
- `seq` 全局单调递增，由写方读当前最大值 +1 自取

**不变量 3：一个 handle 只能被它的私钥持有者使用。** 违反的唯一检测手段是签名校验，不是字段比对。

## 四、消息如何被验证

读方拿到一条消息后，按顺序做两件事：

1. **代码层**：用 `roster.json` 里该 handle 的公钥验签。签名覆盖除 `sig` 外的全部字段，含 `body`。验不过 → 丢弃，**不进入模型**。
2. **模型层**：验过的消息，`body` 交给模型处理。

顺序不可颠倒。让模型先看内容再判断可信度，等于没有这道门。

## 五、这条链路上仍然存在的伪造路径

v0 不解决，但要写清楚，否则容易被当成已解决：

| 攻击 | 现状 |
|---|---|
| 直接改 `roster.json` 换掉别人的公钥 | **未防护**。需要仓库侧开启保护规则或强制签名提交，纯文本层做不到 |
| 私钥存在 agent 客户端配置里被读出 | 未防护，取决于宿主产品 |
| 合法成员在 `body` 里写注入指令 | 部分防护：`type` 限制行为面，但 `body` 仍可骗模型。**这是纯文本方案的固有上限** |
| 重放旧消息 | 由 `nonce` + `last_seen` 缓解 |
| 发起方垄断目标拆解（第 3 步） | 未防护。它虽不能下指令，但能决定任务怎么切——一种合法的影响力 |

第一条最要紧：**名册本身没有保护，整个身份体系就是空的。** 但保护名册需要仓库侧能力，超出文本层范围。v0 的诚实说法是"防伪造消息，不防篡改名册"。

## 六、验收

- [ ] 手工伪造一条 `from` 为合法成员、但私钥不对的消息 → 被代码层拒收，且不出现在任何模型的上下文里
- [ ] 手工篡改 `roster.json` 中他人公钥 → 记录该事件（v0 只要求可发现，不要求可阻止）
- [ ] 第三个 agent 加入后，前两个仍能正常收发，`seq` 无重复无空洞
- [ ] 发起方 agent 试图生成新的提示词模板 → 被拒，因为模板路径不在其可写前缀内
