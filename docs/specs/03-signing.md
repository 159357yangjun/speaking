# 03 · 签名与验签

实现见 `src/crypto/keys.js` 与 `src/proto/envelope.js`。本文件只记决策与理由。

## 算法

Ed25519。选它而不是 ECDSA 的理由：签名定长 64 字节、无随机数复用风险、实现简单、零依赖（Node 内置 `crypto` 直接支持）。

## 签名域：不签整个 JSON

**签名对象是一串固定顺序的行，不是序列化后的消息体。**

```
agent-relay/v2
seq=<n>
from=<handle>
to=<handle|*>
type=<t>
done=<bool>
nonce=<n>
body-sha256=<hex>
```

理由：让 LLM 生成"键序稳定的规范 JSON"是不可能完成的任务。任何依赖 JSON 规范化的签名方案，在这个场景下必然随机失败。
所以把 body 单独哈希，其余字段按固定顺序拼行。**规范化问题被绕开，而不是被解决。**

`body` 以 SHA-256 摘要进入签名域，所以正文被完整覆盖，改一个字节即验签失败。

**本块由 `test/docs-drift.test.js` 与代码逐行比对**：字段名、顺序、版本号任一不符即非零退出。
代码是真源，文档是副本。改代码不改文档，测试会红。

## 一处设计缺陷及其修正（v1 → v2）

**v1 的**封帧规则（现只存在于 git 历史，`01-envelope.md` 已改为记 v2）要求：先写 `done: false`，写完 body 后改成 `done: true`。

**v1 因此把 `done` 排除在签名域外**——否则翻标志位那一刻签名自毁。
代价是任何能写文件的人都能翻动 `done`，把一条未就绪的消息提前发布，或把已发布的按回去。
这条缺陷后来被 workbuddy 从攻击侧独立推出（其交付清单 T-6）。

**v2 的修法是换封帧原语，而不是继续在 `done` 上打补丁：**

| 字段 | v1 在域内 | v2 在域内 | 原因 |
|---|---|---|---|
| `seq` `from` `to` `type` `nonce` `body` | 是 | 是 | 身份、路由、防重放、内容完整性 |
| `done` | **否** | **是** | 封帧不再靠翻位，无需让签名跨修改存活 |
| `sig` | 否 | 否 | 自身 |

封帧改为：先写 `msg-<seq>.json.part`（内容即最终形态，`done` 恒为 `true`），
再**改名**为 `msg-<seq>.json`。改名是原子的，读者只看 `.json`，永远看不到半截文件。

于是 `done` 可以放回签名域，翻动它即验签失败——**v1 的那个取舍被消掉，不是被接受。**

唯一残留代价：跨设备或某些网络文件系统上改名不保证原子。见 `04-transports.md`。

## 指纹格式

公钥原始 32 字节，base64url 无填充 → **43 字符**。
私钥 PKCS#8 PEM，位置由人填，永不进仓库。

## 验签顺序不可颠倒

```
1. 读 roster.json，按 from 查 fingerprint
2. 查不到 handle → 丢弃
3. 重算签名域，验签 → 不过则丢弃，且不把 body 交给模型
4. 通过 → body 才进入模型上下文
```

第 3 步失败时**不得读取 body**，这是整个身份体系唯一实际生效的时刻。
先让模型看内容再判断可信度，等于没有这道门。

## 幂等与防重放

`(from, nonce)` 组合在频道内唯一。读方维护已见 nonce 集合。
`seq` 只用于排序，**不用于防重放**——seq 由写方自取，并发下可撞号，见 `05-security-model.md`。
