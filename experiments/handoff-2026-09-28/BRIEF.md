# 任务：跨 Agent 协作可行性笔记（中文成稿）

## 这个任务本身是一次实验
两个不同厂商的 agent（Qoder 与腾讯 WorkBuddy）在**没有任何一方开放被调用接口**的前提下，
通过同一个本地目录交接，完成一份笔记。协议能不能跑通，和笔记质量同等重要。

## 分工
| 谁 | 负责 | 写到哪 |
|---|---|---|
| Qoder（已完成） | 事实核查、证据、来源链接、结构骨架 | `EVIDENCE.md` |
| **WorkBuddy（你）** | 把证据改写成一篇能直接发出去的中文技术笔记 | `NOTES.md` |

## 你要做的（严格按此执行）
1. 读 `EVIDENCE.md`，全部事实以此为准，**不要新增未经核实的事实、不要编造链接**。
2. 产出 `NOTES.md`，要求：
   - 标题自拟，正文 800–1200 字
   - 开头三句话内讲清结论（读者不看后半段也能拿到判断）
   - 必须包含一节「这个限制意味着什么」，解释"MCP 单向、A2A 要求双方开端口"对做产品的实际影响
   - 结尾给出一条可执行的下一步建议
   - 不要列表堆砌，用连贯段落；技术名词首次出现给一句白话解释
3. 完成后更新 `STATUS.json`：把 `workbuddy.status` 改为 `"done"`，`wrote` 填 `["NOTES.md"]`，`phase` 改为 `"workbuddy-done"`。

## 边界
- 只允许创建/修改 `NOTES.md` 和 `STATUS.json`。不要改 `BRIEF.md`、`EVIDENCE.md`。
- 不要访问该目录以外的文件。

## 验收标准（Qoder 会逐条读回校验）
- [ ] `NOTES.md` 存在且字数在区间内
- [ ] 文中每个事实都能在 `EVIDENCE.md` 找到对应条目
- [ ] 没有出现 `EVIDENCE.md` 之外的 URL
- [ ] `STATUS.json` 的 phase 已更新
