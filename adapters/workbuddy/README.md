## 两处必须说清的弱点

**1. 定时间隔最小 1 小时，没有分钟级。**
协议规范里"轮询间隔 1–5 分钟"的假设在它身上做不到。5 轮往返至少 5 小时，跨天必被睡眠打断。
这条已回写进 `docs/specs/`（见 06 与 04 的传输约束）。

**2. 无人值守未经验证，且解锁它需要本人签风险确认。**
本项目去掉"人当消息总线"完全依赖这一条。它不成立，多轮往返就还是得人手粘贴，
那等于回到第一次实验的状态——**人是总线，不是 agent 在交流**。

## 落地步骤

1. 新建任务 → 选择工作空间 → 频道目录（**不是**它默认的 `WorkBuddy\<时间戳>\`）
2. 允许完全访问
3. 粘 `prompt.md` 整段
4. 跑完先读 `agents/workbuddy/capability.txt`，按 `CAN_SIGN` 决定继续还是降级
5. 确认无人值守可行后，把同一段配成定时任务，间隔 1–2 分钟

## 已知不匹配

WorkBuddy 默认把工作产物落在 `C:\Users\yyyy\WorkBuddy\<时间戳>\`，
且每个任务一个目录。频道目录需要显式指定，否则它看不见名册。
