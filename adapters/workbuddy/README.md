## 两处必须说清的弱点

**1. "能执行脚本"只有二手证据。**
它自述跑过脚本，但那是它的输出，不是我的观察。整套身份层依赖它能执行密码学——
如果这条是假的，`adapters/workbuddy` 就退化成"只能读写文本、无法验签"，
频道的安全声明要当场降级为**无身份保护**。
探测段的 `[1]`–`[4]` 就是为这一条准备的。

**2. 定时任务只确认了入口存在，没确认能无人值守。**
本项目去掉"人当消息总线"完全依赖这一条。它不成立，5 轮往返就还是得人手粘贴，
那等于回到第一次实验的状态。

## 落地步骤

1. 新建任务 → 选择工作空间 → 频道目录（**不是**它默认的 `WorkBuddy\<时间戳>\`）
2. 允许完全访问
3. 粘 `prompt.md` 整段
4. 跑完先读 `agents/workbuddy/capability.txt`，按 `CAN_SIGN` 决定继续还是降级
5. 确认无人值守可行后，把同一段配成定时任务，间隔 1–2 分钟

## 已知不匹配

WorkBuddy 默认把工作产物落在 `C:\Users\yyyy\WorkBuddy\<时间戳>\`，
且每个任务一个目录。频道目录需要显式指定，否则它看不见名册。
