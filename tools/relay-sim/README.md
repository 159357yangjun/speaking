# relay-sim · 协作机制推演器

证明一件事：**markdown 表做"文件占用声明"接不住并发，独占锁能。**
不是观点，是可重跑的用例。

## 跑

```
npm test                      # 含本推演的 6 条断言，约 7 秒
node tools/relay-sim/sim.js <空目录>            # 人读输出
node tools/relay-sim/sim.js <空目录> --json     # 末尾追加一行 RESULT_JSON
```

不联网、不装依赖、不碰真实频道目录。工作目录由脚本独占，跑完自己清（`npm test` 用临时目录）。

## 四个场景与判据

| 场景 | 旧机制（markdown read-modify-write） | 新机制（独占锁 + 强制 TTL） |
|---|---|---|
| S1 正常串行 | 通过 | 通过 |
| S2 并发抢同一文件 ×5 | **谎报成功 5/5** | **谎报 0/5**，每轮恰好 1 领取 + 1 受阻 |
| S3a 脏声明、允许 `ttl=0` | 永久阻塞 | 拒绝领取（退出码 6） |
| S3b 脏声明、`ttl=1` | — | 老化后抢占成功，卡住时长 ≈ TTL |
| S4 抢占后原方回来提交 | — | 拒绝（退出码 5），板上不多记录 |

**谎报成功数 = 自称领到的人数 − 实际持有者数。**
不用"板上剩几行"当指标，因为那看不出**谁被骗了**——被覆盖那方仍以为自己持有锁，会照常改文件。

## 竞态窗口是怎么造出来的

子进程在"读板"与"写回板"之间忙等 300ms，模拟两个 AI 各跑一轮工具调用的真实间隔。
并发用 `spawn` + 一个等待子进程轮询 pid 实现，**不能用 `spawnSync`**——那是顺序执行，测不出竞态。

## 断言为什么不比"几轮撞上"

`test/sim.test.js` 对旧机制只断言 `lieOld >= 1`（存在谎报），不断言等于 5。
竞态是概率性的，写死 5 会在负载高的机器上假红。
但**它必须至少红一次**——如果连一次都没有，说明并发窗口没打开，**那是测试失效，不是机制变好**，所以这条也写成断言并附了说明。

## 已知它管不到的

1. **被拒提交的一方已经改过文件。** 机制证明谁有资格写板子，证明不了谁有资格写文件。
2. **跨文件的语义耦合。** 两个 AI 各改一个不同文件、板上两行都合法，但两者必须同步（本轮真实发生过：签名域 v1/v2 分裂）。板子表达不了。
3. **TTL 拍多长仍是猜的。** 新机制把"无穷"变成"约等于 TTL"，是把不可控变成可调参数，不是消除问题。

## 改动协议后该看什么

`sim.js` 里的机制与 `src/proto/envelope.js` 的封帧规则应当一致：
都用**独占创建 / 改名**作为原子边界，都不靠翻位封帧。
若哪天有人把封帧改回"先写 false 再翻 true"，S2 与 `test/protocol.test.js` 里那条 T-6 会同时红。
